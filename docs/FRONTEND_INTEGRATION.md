# Frontend integration (real backend)

Checked against `api/app/routers/public.py`, `api/app/schemas/`, `docs/contract/error-codes.md`
and the real-backend smoke test (`sim smoke`, 41/41 checks passed with `ABUSE_ENFORCE=true`).
The frozen contract is `docs/contract/openapi.json`; if this page and it ever disagree, the
contract wins.

## 1. Start the backend

macOS / Linux / Windows PowerShell (same commands):

```
uv run fd secrets          # once: writes .env from .env.example
uv run fd migrate          # applies api/migrations (starts Postgres)
docker compose up -d --wait api    # Postgres 16 + Redis 7 + api
uv run fd up               # alternative: the whole stack incl. web (Vite on :5173)
```

Required in `.env` (all generated by `fd secrets`): `POSTGRES_PASSWORD`, `APP_DB_PASSWORD`,
`DATABASE_URL`, `REDIS_URL`, `SESSION_SECRET`, `TOKEN_SIGNING_KEY`, `PHONE_PEPPER`, `ADMIN_KEY`,
`SIM_TELEMETRY_KEY`. Useful: `SIM_MODE=true` (returns `dev_otp` so the UI can show the code;
must be false in prod), `API_RELOAD=false` + `UVICORN_WORKERS=4` for demos.

**Abuse protection:** add `ABUSE_ENFORCE=true` to `.env` and recreate the api
(`docker compose up -d --force-recreate api`). Default is off. The evaluation evidence was
produced with it ON.

Postgres is the only source of truth; Redis is required for sign-in (OTP codes live there).
If Redis is down, sign-in answers `503 SERVICE_UNAVAILABLE`; losing Redis may cost speed, never correctness (invariant 3).

Health: `GET /api/healthz` (process up) and `GET /api/readyz` (`postgres`/`redis` up|down).

## 2. Base URL

All routes are under **`/api`**. In the browser use the relative path `/api/...`: the Vite dev
server proxies `/api` to `http://api:8000` (`web/vite.config.ts`), and `web-prod` (nginx) does
the same. Directly from the host: `http://localhost:8000/api`.

## 3. Endpoints the user app needs

| Step | Call | Success | Notes |
|---|---|---|---|
| Drop info | `GET /api/drops/{drop_id}` | 200 `DropOut` | public; phase, capacity, times |
| Ask for code | `POST /api/auth/otp/request` `{phone, device_id}` | 200 `{request_id, expires_in_s, dev_otp}` | same phone within 30 s returns the same `request_id`; `dev_otp` only with SIM_MODE |
| Verify code | `POST /api/auth/otp/verify` `{request_id, otp, device_id}` | 200 `{session_token, user_public_id}` + `fd_session` cookie | code is single use; `device_id` must match the request |
| Enter | `POST /api/drops/{drop_id}/entries` `{}` | **201** first time, **200** on every repeat (same `entry_id`) | needs session; idempotent per user, so double clicks are harmless |
| Status | `GET /api/drops/{drop_id}/me` | 200 `{phase, entry, allocation, poll_after_ms}` | the UI's single source of truth; poll every `poll_after_ms` |
| Step-up | `POST /api/drops/{drop_id}/step-up` `{otp}` + `Idempotency-Key` | 200 | only when `entry.status == STEP_UP_REQUIRED`; `/me` shows `dev_otp` in SIM_MODE |
| Claim | `POST /api/drops/{drop_id}/claim` `{admission_token}` + `Idempotency-Key: <uuid>` | 200 `{allocation_id, seat_no, confirmed_at}` | token comes from `/me` `entry.admission_token` |
| Draw proof | `GET /api/drops/{drop_id}/draw-proof` | 200 | public, after the draw |

`device_id`: 8–128 chars of `A-Z a-z 0-9 . _ : -`. Generate once per browser
(`crypto.randomUUID()`), store in `localStorage`, send it on both OTP calls.

`/me` `entry.status`: `REGISTERED`, `OFFERED`, `STEP_UP_REQUIRED`, `WAITLISTED`, `NOT_SELECTED`,
`ALLOCATED`, `OFFER_EXPIRED`, `DISQUALIFIED` (stop polling on `ALLOCATED`, `NOT_SELECTED`,
`OFFER_EXPIRED`, `DISQUALIFIED`). `phase`: `SCHEDULED`, `OPEN`, `CLOSED`, `DRAWN`, `CLAIMING`,
`DONE`. In FIFO mode a token appears in `/me` while the drop is OPEN; in Fair mode only after
the draw, for `OFFERED` entries.

## 4. Session

The verify call sets an HttpOnly `fd_session` cookie (path `/api`) **and** returns
`session_token`. Same-origin through the proxy, the cookie alone is enough (use
`credentials: "same-origin"`). Otherwise send `Authorization: Bearer <session_token>`. The cookie
wins if both are sent. A session survives refreshes, second tabs and Wi-Fi ↔ mobile switches
(IP is never part of the session).

## 5. Errors (every error is `{"error": {"code", "message", "retry_after_ms"?}, "server_time"}`)

- **429** (`RATE_LIMITED`, `OTP_THROTTLED`): wait `error.retry_after_ms` (or the `Retry-After`
  header, seconds) plus a little jitter, then retry the same request. Keep the user on the
  current screen; show a countdown only for `OTP_THROTTLED`.
- **401** `UNAUTHENTICATED`: session missing or invalid, go to sign-in. `OTP_INVALID`: wrong
  code, let the user retype. `TOKEN_INVALID` on claim: re-read `/me` for a fresh token and retry
  once with the **same** `Idempotency-Key`.
- **403** `WINDOW_NOT_OPEN` (wait for open), `WINDOW_CLOSED` (registration over), `NOT_OFFERED`.
- **409** `SOLD_OUT`, `OFFER_EXPIRED`: final result screens. **410** `OTP_EXPIRED`: request a new code.
- **423** `STEP_UP_REQUIRED`: show the step-up screen.
- **5xx**: `503 SERVICE_UNAVAILABLE` is retryable (honour `Retry-After`, exponential backoff,
  same idempotency key): show "Reconnecting... your place is safe". Nothing was written. `500`:
  retry a few times, then show the message (it carries a request id).

## 6. Repeated / duplicate claims

Generate one `Idempotency-Key` (UUID) per claim tap and reuse it for every retry of that tap.
Same key → the same 200 body. A new key for the same entry → still the same seat (200), never a
second seat. Two tabs claiming at once → both get the same seat. No key → 400
`IDEMPOTENCY_KEY_MISSING`. Someone else's token → 401 `TOKEN_INVALID`.

## 7. Minimal user journey

1. Load drop (`GET /drops/{id}`), show phase and countdown.
2. Phone → `otp/request` → code screen (show `dev_otp` in demo) → `otp/verify`.
3. "Enter" button → `POST entries` (201/200 both mean "you're in"). Disable nothing on repeat.
4. Poll `/me` every `poll_after_ms`. Show "Registered" → after the draw "Offered" / "Waitlisted"
   / "Not selected".
5. On `OFFERED`: "Claim" → `POST claim` with a fresh `Idempotency-Key`, retry with the same key
   on 429/503. Show `seat_no` from the response (or `/me.allocation`).
6. Every 429 → wait `retry_after_ms`, retry. Every 401 `UNAUTHENTICATED` → sign in again.

## 8. curl checks

```
# 1. health
curl -s http://localhost:8000/api/readyz

# 2. create a drop and open it (admin)
KEY=$(grep ^ADMIN_KEY= .env | cut -d= -f2)
DROP=$(curl -s -X POST localhost:8000/api/admin/drops -H "X-Admin-Key: $KEY" -H 'content-type: application/json' \
  -d '{"name":"demo","capacity":50,"mode":"fair","window_s":300,"claim_window_s":120}' | python3 -c 'import sys,json;print(json.load(sys.stdin)["drop_id"])')
curl -s -X POST localhost:8000/api/admin/drops/$DROP/phase -H "X-Admin-Key: $KEY" -H 'content-type: application/json' -d '{"action":"open"}'

# 3. sign in (SIM_MODE returns dev_otp)
curl -s -X POST localhost:8000/api/auth/otp/request -H 'content-type: application/json' \
  -d '{"phone":"+919812345678","device_id":"dev-demo-0001"}'
curl -s -X POST localhost:8000/api/auth/otp/verify -H 'content-type: application/json' \
  -d '{"request_id":"<request_id>","otp":"<dev_otp>","device_id":"dev-demo-0001"}'

# 4. enter twice (201 then 200, same entry_id), then status
curl -s -i -X POST localhost:8000/api/drops/$DROP/entries -H "Authorization: Bearer <session_token>" -H 'content-type: application/json' -d '{}'
curl -s localhost:8000/api/drops/$DROP/me -H "Authorization: Bearer <session_token>"

# 5. claim after the draw (close + draw as admin first), same key twice -> same seat
curl -s -X POST localhost:8000/api/drops/$DROP/claim -H "Authorization: Bearer <session_token>" \
  -H "Idempotency-Key: 6f1c2b8e-0000-4000-8000-000000000001" -H 'content-type: application/json' \
  -d '{"admission_token":"<entry.admission_token from /me>"}'
```

"uv sync --frozen -q && sim smoke --base-url http://api:8000"` (expects 41/41).
