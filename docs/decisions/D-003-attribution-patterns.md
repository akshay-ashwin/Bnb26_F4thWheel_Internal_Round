# D-003 — Narrower, trailer-aware attribution patterns; fail-closed hooks

Date: 2026-10-04  ·  Raised during: Plan 01 (human-directed)  ·  Status: ADOPTED

## The original plan said

Plan 01 §4.3: the `commit-msg` check rejects a message that contains, case-insensitively, any of `co-authored-by: claude`, `noreply@anthropic.com`, `generated with claude`, `claude code`, `anthropic`, or the robot emoji. The `pre-push` check scans message, author and committer fields for the same patterns. It does not say what a hook does when `uv` is missing.

## What we do instead

**Commit message** (whole message, case-insensitive) is rejected when it has any of:

1. A trailer line whose key is `Co-Authored-By`, `Co-developed-by`, `Assisted-by`, `Reviewed-by`, `Signed-off-by`, `Generated-by`, `Suggested-by` or `Helped-by` and whose value contains `claude` or `anthropic`.
2. The address `noreply@anthropic.com` anywhere.
3. A "generated with/by Claude" line (`generated with [Claude Code]`, `generated by claude`).
4. A Claude Code URL: `claude.com/claude-code`, `anthropic.com/claude-code` or `claude.ai/code`.
5. The robot emoji (U+1F916).

**Author and committer name and email** (commit-msg for the commit being made, pre-push and CI for every commit in range): rejected if the name or the email contains `claude` or `anthropic`. This stays broad on purpose; an AI name in an identity is never legitimate.

**Fail closed.** Each shim checks `command -v uv`; if `uv` is missing it prints "uv is not installed or not on PATH ... Install uv, then run: uv run fd doctor" and exits 1. If `git` cannot read an identity or the pushed range, the check blocks instead of passing.

**Where it runs.** Logic is in `tools/fd/attribution.py`, called as `uv run fd attribution-check commit-msg <file>`, `pre-push` (git's stdin) or `range <revspec>` (CI). Git is run in the hook's working directory, so worktrees and other checkouts are scanned correctly.

## Why it is better (evidence)

- **The old list rejects our own legitimate commits.** The words `claude code` and `anthropic` alone block messages such as "chore: disable Claude Code attribution in project settings", which Plan 01 needs, and any doc commit that explains Rule R1. The test `AllowedMessages` in `tools/tests/test_attribution.py` pins these examples.
- **The old list misses attribution that does not use `Co-Authored-By`.** `Co-developed-by:`, `Assisted-by:` and `Reviewed-by:` trailers and a Claude Code URL carry the same attribution. They are now covered; each has a test.
- **Failing open on a missing `uv` would silently disable R1** on a fresh machine. Failing closed with a pointer to `fd doctor` costs one clear error message.
- Verified: the end-to-end tests drive the real shims in a throwaway repository (clean commit passes; AI trailer, AI author identity and a pushed AI-authored commit are rejected; missing `uv` blocks). A hand run on a throwaway branch of this repository rejected four forbidden commits with zero commits created and accepted a clean control commit.

## Limits (stated plainly)

- Git hooks are local; `git commit --no-verify` skips them and cannot be blocked client-side. The CI `fd attribution-check range` job is the backstop, and Rule R1 forbids `--no-verify`.
- A message can still carry attribution in words the patterns do not anticipate. The patterns are a guard against the known forms, not a proof of absence; the pre-push review in R1 remains a human step.

## Invariants check

All eight invariants are unaffected (tooling for commit hygiene only). Rule R1 is preserved and extended (more trailer keys, URL, fail-closed behaviour).
