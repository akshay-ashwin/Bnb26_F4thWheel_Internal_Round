# Review log — Plan 16: user journey UI (lean mode)

**Contract change: none.** **Built:** the Plan 15 parts Plan 16 needs (`web/src/api/`: client, server clock, idempotency keys, retry policy, connectivity; `web/src/lib/`; base components), then `/drop/:dropId` (every screen in plan §5 except the QR placeholder), `/how-it-works`, the error table in `web/src/features/user/README.md`, the `e2e` compose profile and `uv run fd test-web --e2e`.
**State rule:** one pure function, `resolveUiState.ts`. It checks in this order: drop not found, then no session (`VERIFY`), then **allocation, then entry status, then phase**. A seat always wins, so neither a stale phase nor an old poll can hide it. A `/me` answer older (by `server_time`) than the one shown is ignored, and this tab's own claim result counts as the allocation until `/me` catches up. Added: `LOADING`, `DROP_NOT_FOUND`, `REGISTRATION_CLOSED` (window over, no entry). `DISQUALIFIED` shows the neutral not-selected screen. FIFO sold-out applies to FIFO drops only.
**Reliability, and the test that proves each:** *refresh*: keys and a "claim pending" marker live in sessionStorage and the screen comes only from `/me` (e2e 2 reloads at 7 states). *Lost response or offline*: the claim reaches the server, the browser goes offline before the answer, the reconnect banner shows, and on reconnect the client retries with the same key; the server replays the result; the export shows exactly 1 allocation and both requests carry 1 key (e2e 4). *Tabs*: one session; confirm in tab 2, and tabs 1 and 3 show the same seat within 4 s (e2e 3). *Expired token*: one fresh token from `/me`, same key, never looped (unit).
**Copy rules:** every sentence is in `copy.ts`. `copy.test.ts` fails on the whole words bot/bots/suspicious/fraud/flagged/try again/retry/refresh/hurry/be quick (case-insensitive; `robot` passes).
